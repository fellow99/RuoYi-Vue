## 项目概述

RuoYi-Vue 是一套基于 Spring Boot + Vue 的前后端分离快速开发框架。本项目规范文档旨在为 RuoYi-Vue 框架的所有核心功能模块提供完整的技术规范说明，包括系统管理、系统监控、系统工具、公共模块和核心框架模块。

本规范文档覆盖：
- **19 个业务模块**（用户、部门、岗位、菜单、角色、字典、参数、通知、个人中心、操作日志、登录日志、在线用户、定时任务、缓存监控、服务器监控、连接池监视、代码生成、系统接口、在线构建器）
- **核心框架模块**（通用模块、框架模块、定时任务模块、系统业务模块）
- **公共模块**（认证授权、首页仪表盘、文件管理、错误页面）

## 文档使用说明

### 适用人员

#### 后端开发人员
- **必读：** `spec.md`、`api.md`、`data-model.md`
- **用途：** 理解业务需求、接口定义、数据结构
- **参考：** `ARCHITECTURE.md`、`STRUCTURE.md`

#### 前端开发人员
- **必读：** `pages.md`、`api.md`、`spec.md`
- **用途：** 了解页面结构、组件设计、接口调用
- **参考：** `TECH.md`（技术栈说明）

#### 测试人员
- **必读：** `spec.md`（验收标准）、`api.md`（接口定义）
- **用途：** 编写测试用例、进行接口测试、UI 测试
- **参考：** 各模块的边界条件和异常处理说明

#### 产品经理
- **必读：** `spec.md`（用户故事）、`overall-plan.md`
- **用途：** 了解功能范围、用户需求、业务流程
- **参考：** `constitution.md`（项目章程）

#### 运维人员
- **必读：** `ARCHITECTURE.md`、`014-cache`、`015-server`、`016-pool`
- **用途：** 了解系统架构、监控指标、部署配置
- **参考：** 各监控模块的配置说明

### 阅读顺序建议

#### 新加入项目
1. `constitution.md` - 了解项目愿景和原则
2. `ARCHITECTURE.md` - 理解系统整体架构
3. `STRUCTURE.md` - 熟悉项目目录结构
4. `TECH.md` - 掌握技术栈选型
5. `overall-plan.md` - 了解整体规划
6. 选择具体模块的 `spec.md` - 深入业务功能

#### 开发新功能
1. 对应模块的 `spec.md` - 理解需求
2. `data-model.md` - 设计数据结构
3. `api.md` - 定义接口
4. `pages.md` - 实现前端
5. 参考相似模块的实现

#### 排查问题
1. `api.md` - 检查接口定义
2. `data-model.md` - 验证数据逻辑
3. `spec.md` - 确认业务规则
4. `ARCHITECTURE.md` - 理解模块依赖

## 维护指南

### 文档更新流程

1. **需求变更时**
   - 更新对应模块的 `spec.md`
   - 同步更新 `data-model.md`、`api.md`、`pages.md`
   - 在文档头部更新版本号和时间

2. **接口变更时**
   - 更新 `api.md` 中的接口定义
   - 通知前后端开发人员
   - 如有破坏性变更，标注迁移指南

3. **数据结构变更时**
   - 更新 `data-model.md`
   - 检查关联模块的文档
   - 更新数据库迁移脚本说明

4. **前端页面变更时**
   - 更新 `pages.md`
   - 更新组件截图（如有）
   - 标注交互逻辑变化

### 版本管理

- 文档版本与代码版本保持一致
- 重大变更时更新主版本号（如 v3.9 → v4.0）
- 小变更时更新次版本号（如 v3.9.1 → v3.9.2）
- 在文档头部维护变更日志

### 质量检查清单

在提交文档前检查：

- [ ] 所有接口示例可运行
- [ ] 数据模型与代码一致
- [ ] 用户故事有明确的验收标准
- [ ] 页面组件图与实际一致
- [ ] 无拼写错误和语法错误
- [ ] 链接和引用有效
- [ ] 版本号和日期已更新

### 文档规范

#### 命名规范
- 模块目录：`NNN-module-name/`（三位数字前缀）
- 文档文件：小写 + 连字符（如 `data-model.md`）
- 图片资源：与文档同名 + 序号（如 `pages-01.png`）

#### 格式规范
- 使用 Markdown 语法
- 代码块标注语言类型
- 表格对齐整齐
- 标题层级清晰（最多 4 级）

#### 内容规范
- 用户故事格式：`作为 [角色]，我想要 [功能]，以便 [价值]`
- 接口文档包含：请求方法、URL、参数、响应、示例
- 数据模型包含：字段名、类型、说明、约束
- 页面文档包含：布局图、组件树、状态流

### 协作建议

- 使用 Git 进行版本控制
- 一人负责一个模块的文档维护
- 重大变更需要 Code Review
- 定期（每季度）审查文档准确性
- 建立文档反馈机制（Issue 或评论）
