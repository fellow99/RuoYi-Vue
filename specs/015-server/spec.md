# 015-server - 服务器监控模块规格

## 概述

服务器监控模块提供对服务器硬件资源、操作系统、Java 虚拟机和磁盘状态的全面监控能力，帮助管理员实时掌握服务器运行状态。

## 用户故事

### US-001 查看 CPU 使用状态
**作为** 系统管理员  
**我想要** 查看 CPU 核心数和使用率  
**以便于** 了解服务器计算资源使用情况

**验收标准：**
- 显示 CPU 核心数
- 显示用户使用率
- 显示系统使用率
- 显示当前空闲率
- 数据实时更新

### US-002 查看内存使用状态
**作为** 系统管理员  
**我想要** 查看物理内存和 JVM 内存使用情况  
**以便于** 监控内存资源分配和使用

**验收标准：**
- 显示物理内存总量、已用、剩余和使用率
- 显示 JVM 内存总量、已用、剩余和使用率
- 使用率超过 80% 时显示警告颜色（红色）
- 内存单位自动转换（GB/MB）

### US-003 查看服务器信息
**作为** 系统管理员  
**我想要** 查看服务器基本信息  
**以便于** 了解服务器配置和环境

**验收标准：**
- 显示服务器名称
- 显示服务器 IP 地址
- 显示操作系统名称
- 显示系统架构
- 显示项目路径

### US-004 查看 JVM 信息
**作为** 系统管理员  
**我想要** 查看 Java 虚拟机详细信息  
**以便于** 了解 JVM 运行状态和配置

**验收标准：**
- 显示 Java 名称和版本
- 显示启动时间和运行时长
- 显示安装路径
- 显示项目路径
- 显示运行参数

### US-005 查看磁盘状态
**作为** 系统管理员  
**我想要** 查看各磁盘分区使用情况  
**以便于** 监控磁盘空间并预防空间不足

**验收标准：**
- 显示所有磁盘分区
- 显示盘符路径
- 显示文件系统类型
- 显示盘符类型
- 显示总大小、可用大小、已用大小
- 显示已用百分比
- 使用率超过 80% 时显示警告颜色（红色）

## 功能需求

### FR-001 服务器信息采集
系统必须采集以下服务器信息：
- CPU 信息（核心数、使用率）
- 内存信息（总量、已用、剩余）
- JVM 信息（内存、版本、运行时间）
- 系统信息（名称、IP、操作系统）
- 磁盘信息（分区、容量、使用率）

### FR-002 实时监控
系统必须支持实时采集服务器状态信息，每次请求返回最新数据。

### FR-003 数据格式化
系统必须将原始数据转换为人类可读格式：
- 字节转换为 GB/MB/KB
- 时间戳转换为日期时间
- 毫秒转换为运行时长
- 小数保留 2 位精度

### FR-004 阈值告警
系统必须对关键指标进行阈值判断：
- 内存使用率 > 80% 时标记警告
- 磁盘使用率 > 80% 时标记警告

### FR-005 权限控制
所有服务器监控操作必须受权限控制，需要 `monitor:server:list` 权限。

## 数据模型

### Server
服务器信息聚合根实体。

**属性：**
- `cpu` (Cpu): CPU 相关信息
- `mem` (Mem): 内存相关信息
- `jvm` (Jvm): JVM 相关信息
- `sys` (Sys): 服务器相关信息
- `sysFiles` (List<SysFile>): 磁盘相关信息

### Cpu
CPU 相关信息。

**属性：**
- `cpuNum` (int): 核心数
- `total` (double): 总使用率
- `sys` (double): 系统使用率
- `used` (double): 用户使用率
- `wait` (double): 等待率
- `free` (double): 空闲率

### Mem
内存相关信息。

**属性：**
- `total` (double): 内存总量 (GB)
- `used` (double): 已用内存 (GB)
- `free` (double): 剩余内存 (GB)
- `usage` (double): 使用率 (%)

### Jvm
JVM 相关信息。

**属性：**
- `total` (double): JVM 总内存 (MB)
- `max` (double): JVM 最大内存 (MB)
- `free` (double): JVM 空闲内存 (MB)
- `version` (String): JDK 版本
- `home` (String): JDK 路径

### Sys
系统相关信息。

**属性：**
- `computerName` (String): 服务器名称
- `computerIp` (String): 服务器 IP
- `osName` (String): 操作系统
- `osArch` (String): 系统架构
- `userDir` (String): 项目路径

### SysFile
磁盘文件分区信息。

**属性：**
- `dirName` (String): 盘符路径
- `sysTypeName` (String): 文件系统类型
- `typeName` (String): 盘符类型
- `total` (String): 总大小
- `free` (String): 剩余大小
- `used` (String): 已用大小
- `usage` (double): 使用率 (%)

## 关键实体

- **SystemInfo**: OSHI 库系统信息对象
- **HardwareAbstractionLayer**: 硬件抽象层
- **CentralProcessor**: CPU 处理器信息
- **GlobalMemory**: 内存信息
- **OperatingSystem**: 操作系统信息
- **FileSystem**: 文件系统信息
- **OSFileStore**: 磁盘分区信息

## 成功标准

### 性能指标
- 服务器信息采集时间 < 2 秒
- 页面加载时间 < 3 秒
- 数据刷新响应时间 < 1 秒

### 可用性指标
- 服务器监控页面可用性 ≥ 99%
- 支持并发查看操作

### 准确性指标
- CPU 使用率误差 < 5%
- 内存使用率误差 < 1%
- 磁盘使用率误差 < 1%

## 假设

1. 服务器运行在 Linux/Windows 操作系统上
2. OSHI 库可正常访问系统硬件信息
3. 用户具有查看系统信息的权限
4. 服务器时间同步正常

## 依赖

- OSHI (Operating System and Hardware Information)
- Spring Boot
- Vue.js + Element UI（前端）

## 约束

1. 某些系统信息可能需要 root/admin 权限
2. 容器环境下部分信息可能不准确
3. 跨平台信息可能存在差异
4. 高频采集可能影响系统性能
