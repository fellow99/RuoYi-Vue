# 操作日志功能规格 (010-oper-log)

**模块编号：** 010  
**模块名称：** 操作日志 (OperLog)  
**最后更新：** 2026-03-12

---

## 一、功能概述

### 1.1 功能描述

操作日志模块用于记录和追踪系统中所有用户的关键操作行为，包括新增、修改、删除、导出、导入等操作。该模块为系统管理员提供完整的操作审计能力，便于问题追溯和安全监控。

### 1.2 核心价值

- **操作审计：** 记录所有用户操作，满足合规要求
- **问题追溯：** 当系统出现异常时，可快速定位操作源头
- **安全监控：** 监控异常操作行为，保障系统安全
- **性能分析：** 记录操作耗时，辅助性能优化

### 1.3 用户角色

| 角色 | 权限说明 |
|------|----------|
| 系统管理员 | 查看、删除、导出、清空操作日志 |
| 普通用户 | 无权限访问 |

## 二、功能需求

### 2.1 日志记录

#### FR-010-001 自动记录
系统应自动记录用户的以下操作：
- 所有新增（INSERT）操作
- 所有修改（UPDATE）操作
- 所有删除（DELETE）操作
- 所有导出（EXPORT）操作
- 所有导入（IMPORT）操作
- 所有授权（GRANT）操作
- 所有强退（FORCE）操作
- 所有生成代码（GENERATE）操作
- 所有清空数据（CLEAN）操作

#### FR-010-002 记录内容
每条操作日志应包含：
- 操作模块名称
- 业务类型（新增/修改/删除等）
- 请求方法和 URL
- 操作人员姓名和部门
- 操作 IP 地址和地点
- 请求参数
- 返回结果
- 操作状态（成功/失败）
- 错误消息（如有）
- 操作时间
- 消耗时间（毫秒）

#### FR-010-003 记录方式
- 采用 AOP 切面方式自动拦截记录
- 异步记录，不阻塞主业务流程
- 支持自定义注解 `@Log` 配置日志信息

### 2.2 日志查询

#### FR-010-004 列表查询
系统应提供操作日志列表查询功能：
- 支持分页显示（默认 10 条/页）
- 支持按操作地址模糊搜索
- 支持按系统模块模糊搜索
- 支持按操作人员模糊搜索
- 支持按操作类型筛选
- 支持按操作状态筛选
- 支持按操作时间范围筛选
- 默认按操作时间倒序排列

#### FR-010-005 排序功能
- 支持按操作人员排序
- 支持按操作日期排序
- 支持按消耗时间排序
- 支持升序/降序切换

#### FR-010-006 详细查看
- 支持查看单条日志的完整信息
- 以弹窗形式展示详细信息
- 显示请求参数和返回参数的完整 JSON

### 2.3 日志管理

#### FR-010-007 批量删除
- 支持单选删除
- 支持多选批量删除
- 删除前需二次确认
- 删除后刷新列表

#### FR-010-008 清空日志
- 支持一键清空所有操作日志
- 清空前需二次确认（警示）
- 清空操作使用 TRUNCATE 方式

#### FR-010-009 导出功能
- 支持将查询结果导出为 Excel 文件
- 导出文件名包含时间戳
- 导出内容包含所有字段

## 三、权限要求

### 3.1 权限标识

| 功能 | 权限标识 | 说明 |
|------|----------|------|
| 查看列表 | `monitor:operlog:list` | 查看操作日志列表 |
| 查看详情 | `monitor:operlog:query` | 查看操作日志详细 |
| 删除日志 | `monitor:operlog:remove` | 删除操作日志 |
| 导出日志 | `monitor:operlog:export` | 导出操作日志 |

### 3.2 权限控制
- 所有接口均需通过 `@PreAuthorize` 注解进行权限校验
- 前端按钮根据权限动态显示/隐藏
- 无权限访问返回 403 错误

## 四、业务规则

### 4.1 业务类型枚举

| 值 | 类型 | 说明 |
|----|------|------|
| 0 | OTHER | 其他 |
| 1 | INSERT | 新增 |
| 2 | UPDATE | 修改 |
| 3 | DELETE | 删除 |
| 4 | GRANT | 授权 |
| 5 | EXPORT | 导出 |
| 6 | IMPORT | 导入 |
| 7 | FORCE | 强退 |
| 8 | GENERATE | 生成代码 |
| 9 | CLEAN | 清空数据 |

### 4.2 操作类别

| 值 | 类别 | 说明 |
|----|------|------|
| 0 | OTHER | 其他 |
| 1 | WEB | 后台用户 |
| 2 | MOBILE | 手机端用户 |

### 4.3 操作状态

| 值 | 状态 | 说明 |
|----|------|------|
| 0 | SUCCESS | 正常/成功 |
| 1 | ERROR | 异常/失败 |

## 五、数据约束

### 5.1 数据量管理
- 建议定期清理历史日志（如保留 3-6 个月）
- 大数据量时建议按时间分表或归档
- 清空操作使用 TRUNCATE，谨慎使用

### 5.2 性能要求
- 日志记录应采用异步方式，不影响主业务响应时间
- 列表查询响应时间 < 2 秒（10 万条数据内）
- 支持按时间范围索引优化查询

---

## 六、异常处理

### 6.1 记录异常
- 操作失败时，记录完整错误消息
- 错误消息截取前 2000 字符，避免超长
- 不影响原业务流程，确保业务正常返回

### 6.2 查询异常
- 查询条件为空时，返回全部数据（分页）
- 查询超时返回友好提示
- 数据库异常记录系统日志

## 八、验收标准

### 8.1 功能验收
- [ ] 所有业务操作能自动记录日志
- [ ] 日志内容完整准确
- [ ] 查询功能正常，支持所有筛选条件
- [ ] 删除功能正常，支持批量删除
- [ ] 导出功能正常，Excel 格式正确
- [ ] 清空功能正常，有二次确认

### 8.2 性能验收
- [ ] 日志记录不影响业务性能（异步）
- [ ] 列表查询响应时间 < 2 秒
- [ ] 支持 10 万 + 数据量正常查询

### 8.3 安全验收
- [ ] 权限控制有效，无权限无法访问
- [ ] 敏感操作有二次确认
- [ ] 日志内容不包含敏感信息明文
