# 002-部门管理 - 功能规格

**模块编号：** 002  
**模块名称：** 部门管理 (Department Management)  
**所属模块：** 系统管理  
**版本：** 3.9.1  
**最后更新：** 2026-03-12

---

## 一、功能概述

部门管理用于配置系统的组织机构，支持树形结构展现。该模块是用户管理、数据权限等模块的基础，为系统提供组织架构支持。

### 1.1 核心功能

- **部门 CRUD**：新增、查询、修改、删除部门
- **树形结构**：支持多层级部门树形展示
- **数据权限**：基于部门的数据范围控制
- **状态管理**：启用/停用部门
- **排序管理**：自定义部门显示顺序

### 1.2 业务规则

1. **部门名称唯一性**：同级部门名称不能重复
2. **树形结构**：支持无限层级（实际建议不超过 5 级）
3. **停用约束**：部门停用前需先停用所有子部门
4. **删除约束**：部门存在子部门或用户时不允许删除
5. **数据权限**：基于部门的数据范围控制用户数据访问

## 二、功能详细设计

### 2.1 部门列表查询

**功能描述：** 以树形结构展示所有部门

**查询条件：**
- 部门名称（模糊匹配）
- 部门状态（0-正常 / 1-停用）

**列表字段：**
- 部门名称、显示顺序、负责人
- 联系电话、邮箱、状态
- 创建时间、操作列

**权限标识：** `system:dept:list`

### 2.2 新增部门

**功能描述：** 创建新的部门

**必填字段：**
- 上级部门（树形选择）
- 部门名称（同级唯一）
- 显示顺序

**可选字段：**
- 负责人
- 联系电话
- 邮箱
- 状态（默认正常）

**业务校验：**
1. 校验同级部门名称是否重复
2. 校验上级部门不能是自己

**权限标识：** `system:dept:add`

### 2.3 修改部门

**功能描述：** 修改部门信息

**可修改字段：** 同新增部门

**业务校验：**
1. 校验部门数据权限
2. 校验同级部门名称是否重复（排除自身）
3. 校验上级部门不能是自己
4. 停用前检查是否有正常子部门

**权限标识：** `system:dept:edit`

### 2.4 删除部门

**功能描述：** 删除部门

**业务规则：**
1. 检查部门数据权限
2. 检查是否存在子部门（有则不允许删除）
3. 检查部门下是否有用户（有则不允许删除）

**权限标识：** `system:dept:remove`

### 2.5 状态修改

**功能描述：** 启用或停用部门

**业务规则：**
1. 停用前检查是否有正常状态的子部门
2. 有正常子部门时不允许停用

**权限标识：** `system:dept:edit`

## 三、权限设计

### 3.1 权限标识清单

| 权限标识 | 权限名称 | 说明 |
|---------|---------|------|
| `system:dept:list` | 部门查询 | 查询部门列表 |
| `system:dept:query` | 部门详情 | 查询部门详细信息 |
| `system:dept:add` | 部门新增 | 新增部门 |
| `system:dept:edit` | 部门修改 | 修改部门信息 |
| `system:dept:remove` | 部门删除 | 删除部门 |

### 3.2 数据权限

部门管理模块本身不应用数据权限过滤（管理员需要看到完整架构），但为其他模块提供数据权限基础。

---

## 四、树形结构设计

### 4.1 树形字段

- `parent_id` - 父部门 ID
- `ancestors` - 祖级列表（逗号分隔的祖先 ID）
- `order_num` - 显示顺序

### 4.2 树形构建

```java
// 构建部门树
List<SysDept> deptTree = buildDeptTree(list);
```

### 4.3 祖级列表

`ancestors` 字段存储从根节点到当前节点的所有祖先 ID，用于：
- 快速查询子部门
- 判断部门层级关系
- 数据权限过滤

## 九、注意事项

1. **树形结构维护**：新增/修改部门时需正确维护 `ancestors` 字段
2. **停用顺序**：停用部门需从下往上（先停子部门）
3. **删除顺序**：删除部门需从下往上（先删子部门）
4. **数据权限**：部门变更可能影响用户数据权限范围
